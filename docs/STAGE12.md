# 阶段十二 · 模型先选工具的创作问答

桌面版启动入口为 `dist/stage12/EasyWriting/EasyWriting.exe`。打开后继续使用原来的作品、独立会话库和本机配置。选中 DeepSeek 后，在「创作问答」发送问题即可使用模型先选工具。离线演示也能演示这一流程。

## 每轮怎么处理

程序先确定作品、章号范围、人物视角、故事时点和知识快照。首次发送给 DeepSeek 的资料包含问题、受限的会话记忆、范围信息与工具定义。模型可以先查章节、人物、事件、关联路径、伏笔或入库状态，也可以先请作者澄清。模型选中的工具由本地程序执行，后续请求才携带工具取得的资料。

| 你问的问题 | 可能使用的工具 |
| --- | --- |
| 第一章写了什么内容？ | `get_chapter_overview` 按章号查摘要和事件 |
| 林舟为什么去旧宅？ | `search_memory` 找到事件，再查 `get_event_details` 或 `get_related_events` |
| 那时他知道密码吗？ | 沿用确认过的指代和时点，通过 `get_character_details` 查询该人物可见的事实 |
| 还有哪些伏笔待回收？ | `list_foreshadowing` 按状态和页次查看 |
| 这个情节在原文中怎么写的？ | 先取得可引用编号，再用 `read_source` 查看局部正文 |

待入库片段须在界面明确允许后，模型才会获得 `read_pending_source` 工具。回复会标明片段属于临时依据。作者视角可以查询故事摘要，人物视角返回该人物可见的事实。改稿造成快照变化时，本轮会提示重新提交。

普通对话每题最多 3 次模型调用、3 次工具请求和 2 次原文读取。深度对话对应上限为 5、8、4。首次工具选择和超限重试计入模型调用额度。问答、工具结果、用量、引用和摘要仍记录在独立会话库。可在桌面版「查看本轮证据与用量」核对。

项目导入和下一章路线从各自的界面入口提交，沿用计划中的固定步骤。入库校验正文出处和版本，路线校验引用、人物认知和规则约束，作者在路线页自行选择是否采纳。

## 验收

离线脚本覆盖了模型在零预检索结果时调用章节工具、事件链追查、同名澄清、人物视角隔离、未入库授权、引用校验、重复查询和过期快照。以「第一章写了什么内容」为例，上一版按章预检索后需要一次生成调用，新入口由模型先选择工具、再生成答复。

同一问题以内置样章实测 DeepSeek，共发起 2 次模型请求、执行 1 次章节概述工具、回查原文 0 次。接口共报告 4753 token，本轮约 2.17 秒。事件链和人物认知追问由离线脚本验证，实际问题的用量和延迟取决于工具结果及模型请求次数。
