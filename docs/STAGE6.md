# 阶段六：下一章路线与本地工作台

本阶段增加 Streamlit 工作台和独立的下一章计划服务，复用前五阶段的入库、知识、检索、原文、时间线与检查功能。

## 1. 打开工作台

本机已安装界面依赖。在项目目录的 VS Code 终端运行：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

打开 `http://127.0.0.1:8501`。项目配置默认只监听本机，关闭 Streamlit 使用统计。服务已运行时直接访问；停止服务使用对应终端的 Ctrl+C。

新环境安装：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,ui]"
# 需要本地 BGE 时安装完整组合：
.\.venv\Scripts\python.exe -m pip install -e ".[dev,ui,semantic]"
```

固定依赖组合如下，均按本机 Windows / Python 3.14.7 环境生成：

| 文件 | 内容 |
|---|---|
| `requirements.lock.txt` | 基础服务与测试 |
| `requirements.ui.lock.txt` | 基础、测试、Streamlit；不包含 Torch |
| `requirements.semantic.lock.txt` | 基础、测试、本地 BGE；不包含 Streamlit |
| `requirements.full.lock.txt` | 界面与本地 BGE 的完整组合 |

可先安装相应锁文件，再执行 `pip install --no-deps -e .`。当前实测 Streamlit 为 1.66.1。其他平台需重新解析兼容组合。

## 2. 四个入口

左侧选择本地数据库与作品，也可以创建新作品。默认数据库沿用 `.env` 的 `DATABASE_PATH`，密钥继续仅保存在本机 `.env`，页面不显示密钥。

### 项目导入

- 空项目可点击“导入内置演示章节”，导入含林舟、林月、钥匙、密码和月牙划痕的人工标注样章。
- 任意小说通过 UTF-8 TXT / Markdown 文件或粘贴正文导入，填写章节号和标题后提交。
- 选 DeepSeek 时，新增或未完成分块会发送至接口；离线服务需要与该章匹配的 `blocks` 提取响应 JSON。固定演示模型不会分析任意正文。
- 修改旧章使用相同章节号。当前版本未完成提取时，章节表显示知识未更新；重试旧失败任务需要明确勾选。

内置样稿的人工确认与认知标注只用于演示，不应用于作者自己的任意正文。

### 知识查看

分页查看事实、人物与实体、事件、伏笔、摘要和连接，展开原文出处与版本。支持确认、否决和修改字段，填写修改原因。

事实支持标注生效 / 结束事件、单值状态模式和角色获知渠道；人物与时间线页面可标注故事时间刻度。伏笔页面可确认生命周期状态或修正已有判断。更复杂的事件连接、合并、规则约束等操作继续使用前期 CLI 服务。

### 创作问答

“创作问答”复用 LangGraph 与只读 Tools，支持关键词 / 本地 BGE、正文边界、故事时点和人物认知范围。选 DeepSeek 并提交后才发送本次受限资料。结果可展开依据、范围、用量和停止原因；知识已变时显示旧回答过期提示。

“下一章路线”填写目标、涉及人物、明确的故事起点与每行一条的限制条件。提交后生成两到三条路线，每条包含依据引用、必要铺垫、有序场景、伏笔影响和所有选中人物的拟议弧线。

“已保存计划”可分页查看既有方案、原文依据与作者决定，不重新调用模型。

### 检查报告

点击运行当前知识检查，分页查看问题、双方原文、判断条件及建议。作者可以标记待处理、暂不处理、有意安排或已处理。旧报告失效时必须先重新检查，再处理当前问题。检查是本地规则操作，不调用模型。

## 3. 路线如何约束认知与规则

资料包区分作者可见事实与每个人物在选定故事时点可证明知道的 `known_keys`，不会把作者掌握的密码直接当作人物已知信息。只采用当前、已确认、明确且时间可排序的有关事实，角色观点另有标识。

路线按有序场景登记信息使用、计划获知及设定断言。信息使用须有当前已知依据；若先由已知信息的在场人物告知，后续场景才可使用。同场景告知来源必须在场景开始时就已知，不能循环互相证明。计划中的获知不会修改真正的角色认知。

已确认世界规则完整纳入资料预算，校验登记的主体 / 谓词 / 值断言。有界规则在规划中保守遵守并提示作者核对未来适用性；来源失效或未确认的规则单独提示覆盖缺口。预算放不下必要规则时停止，不静默漏掉约束。

引用只允许来自返回的资料，主体编号须可解析。对唯一匹配的伏笔标题可规范成已有伏笔编号；同名歧义拒绝。已开放、取消或回收的伏笔不强制再次回收。路线标题与场景序列重复、缺少选中人物、错误引用或违反认知 / 规则校验时，草稿不能成为可采纳计划。

这些是结构化约束与引用校验，不是完整自然语言语义证明。未登记的信息使用、谓词同义表达、角色动机、自由文本限制和隐含世界规则仍需作者审阅。模型的创作建议不能充当已确认性格或历史事实。

规划资料默认 16000，完整输入估计预算 40000，界面输出上限 3072 token。输入预算沿用 UTF-8 字节估计，含系统指令、资料和 JSON Schema 的估算；不是供应商精确 tokenizer 或计费硬上限。实际用量读取接口返回，并保留调用编号。检索资料只按需筛选，全部未回收伏笔盘点仍使用第五阶段的完整分页服务。

## 4. 保存、采纳与正文关联

计划与事实分表保存，具有独立状态：

```text
生成草稿 → 作者选择路线并说明原因 → 已采纳
                                    ↓
                 作者写成目标章并完成正常入库
                                    ↓
                       关联当前正文版本 → 已关联正文
```

草稿或未写入正文的已采纳计划可舍弃。采纳要求依据快照仍有效；正文关联要求计划先被采纳，且版本确为同一作品、目标章节的当前已发布版本。

“已关联正文”记录作者确认，不是系统证明正文实现了每个情节。真正进入已发生知识的内容仍由正常正文入库与证据核验产生，系统不会把路线描述直接复制成事实、事件、获知或伏笔状态。

## 5. 重运行、失败和重新校验

所有付费入口都由明确的表单提交触发。页面重运行、切换作品、展开依据、查看计划与历史，只读取保存的数据。任务编号在 SQLite 中先登记，执行与结果分离：

- 同一任务号和请求重复执行返回已有结果；同时运行的重复请求会被阻止。
- 同一任务号不能更换参数、项目或规划模型配置。
- 失败或服务中断的任务不会自动接管、重发或轮询重试。再次提交代表作者明确新建任务，旧请求是否计费需查原调用记录。
- 界面模型适配器关闭内部自动重试；问答仍受原有多轮 / 工具预算约束，长章入库仍可能包含多个分块请求。
- BGE 只在明确提交语义检索时加载，在当前会话复用；不会因打开页面自动下载模型。

未通过路线校验的返回草稿保存在失败任务里供审阅，不是可采纳计划；同时保留用量和调用编号。作者补齐确有依据的认知渠道后，可点击“仅重新校验草稿，不调用模型”。复核只复用旧草稿，不产生新模型请求；人物身份、引用事实、伏笔或规则内容已变则拒绝复用，要求重新生成。原调用用量在源任务查询，复核不重复记为新计费请求。

任务记录绑定数据库与项目，可分页查看；不会因切换作品展示另一作品的结果。任务结果与草稿可能包含小说资料，保存在已忽略的本地 `data/` 数据库中；调用元数据日志继续不保存提示或回复。

## 6. 验收与数据升级

离线演示：

```powershell
.\.venv\Scripts\python.exe scripts/demo_stage6.py
```

在左侧打开 `data/stage6_demo/novel.db`，即可查看演示作品。每次脚本运行创建独立演示项目，不重置作者历史。报告为同目录 `stage6_acceptance.json`、`stage6_plan.json`。

可手动做一次真实规划验收：

```powershell
.\.venv\Scripts\python.exe scripts/demo_stage6.py --provider deepseek --db data/stage6_live/novel.db
```

此命令会新增实际请求和用量；模型若返回违反约束的方案，会被拒绝并保留失败记录。不要将脚本的断言通过率当成任意小说的创作质量评测。

本轮真实验收共手动发起 2 次 DeepSeek 请求，输入 6148、输出 4502、合计 10650 token。两次返回起初被严格认知检查拦截，发现内置样稿漏标注林舟对自己持有钥匙的自知；明确补记后，第二份既有草稿规范了唯一伏笔标题引用，再经本地复核成为两条可采纳路线，未追加模型请求。结果见 `data/stage6_live/stage6_live_acceptance.json` 与 `stage6_live_plan.json`。当前内置样稿已补齐该人工标注。

数据库升级至 v5，新增持久任务、下一章计划和计划决定历史。旧 v4 库首次打开前保留 `.pre-v5.bak`。已有数据的 v4 库副本迁移通过：375 条伏笔、12 份检查报告及原有各表记录数保持，外键与备份可打开，原始库保持原状。

页面交互使用 Streamlit AppTest 验收，覆盖四入口、知识修改、检查运行、缺失密钥恢复、一次提交后的页面重运行和作品隔离；本地服务健康接口返回 HTTP 200。浏览器目视验收因电脑操作授权超时未完成，本轮未声称完成浏览器截图检查。

完整回归 239 项通过，其中本阶段新增 26 项、页面交互 6 项。`pip check` 无依赖冲突，wheel 构建与新模块、v5 迁移资源检查通过。离线验收不会调用真实 DeepSeek。
