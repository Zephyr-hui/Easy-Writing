# 阶段八 · 多轮创作对话

## 工作台用法

启动工作台并选择作品，打开 **创作问答 → 创作问答**。发送第一条消息自动创建会话，也可以先点击 **新建会话**。重新打开工作台后，从 **继续会话** 选择已保存的会话。

1. 查询人物时可使用姓名或别名。例如先问“林舟参与了哪些事件？”，再问“他当时知道密码吗？”。有同名人物或时点不明确时，可选择 **明确查询对象** 或 **故事时点**。指定正文截止章、故事时点和人物视角后，检索与历史上下文遵循该范围。
2. 查询事件时可使用名称或情节描述。例如“交出钥匙的前因后果是什么？”。答复可以引用参与者、首次可见提及、故事时间和已确认的关联。时间先后和因果分别呈现。
3. 讨论写作时可以填写 **创作目标** 与 **作者约束**，也可以在聊天中追问“保留现有伏笔，延后揭晓，要补什么铺垫？”。展开 **依据、范围与调用用量** 可查看证据。需要正式路线时，点击 **将创作目标和约束带入下一章路线**，在路线表单确认后单独生成。
4. 涉及较长的事件链时，在提交前勾选 **深度对话（仅本次提问）**。该轮结束后开关复位。尚未入库的已保存正文须另行勾选许可，返回片段会标记为临时依据。

离线演示使用固定模板。选择 DeepSeek 后，本轮问题、相关会话上下文、知识条目和必要的原文片段会发送至接口。

## 会话存储与范围

SQLite v7 增加会话表和轮次表，答复、引用和用量复用工作台任务记录。项目和数据库共同决定可访问的会话。打开 v6 库时按原迁移机制创建 `.pre-v7.bak`。完整 SQLite 备份包含对话记录。

完整消息保存在本地。每轮按预算选取已确认对象、创作目标、约束、近期消息，以及匹配当前主题的旧对话摘录。历史对话用于理解指代和写作意图，事实从当轮知识库及只读工具取证。改稿后旧答复显示依据过期。缩小章节范围或切换人物视角时，只复用同范围、同知识快照的历史内容。角色视角只检索该人物的获知命题。

## 深度对话的调用范围

| 模式 | 模型调用 | 工具调用 | 局部原文读取 |
| --- | ---: | ---: | ---: |
| 普通 | 3 | 3 | 2 |
| 深度 | 5 | 8 | 4 |

表中为单次提问的试行上限。LangGraph 在同一次提问中保留已获取的工具结果。深度模式允许沿指定关系查询相关事件，每次最多展开两跳、八个节点，单轮最多纳入二十四个关联节点。一次请求的估计输入上限为 12000，深度模式整轮累计估计上限为 48000，单位为保守的 UTF-8 字节估计。实际计费用量取自接口返回值。

重复查询会被拦截。证据已经足够、没有取得新证据或预算将耗尽时进入答复阶段。回复需要说明查证范围及未解决的问题，小说正文和正式知识继续由现有入库及审核流程维护。

## 验收

离线样稿验证了会话恢复、长对话中的旧主题与约束、指代和时点、同名澄清、改稿后引用过期、未入库原文授权、项目与人物视角隔离、刷新防重复提交，以及 v6 至 v7 的迁移备份。事件链样稿中，普通模式在 3 次模型调用内收尾，深度模式用 4 次模型调用和 3 次工具调用汇总了 6 条因果连接，原文回查 0 次。模型响应由测试脚本控制，真实 DeepSeek 的自由对话质量仍需使用小说样稿评测。
